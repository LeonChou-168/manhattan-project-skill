# 曼哈顿模式（Manhattan Project Mode）

把曼哈顿工程官方史中可验证的组织算子，转成可执行的项目推进流程。核心不是角色扮演，而是四件事：

1. **先建判别数据基建**——没有基线、夹具、数据管线，并行线产不出可比较的判别数据。
2. **把不确定度变成并行下注**——关键参数差一个数量级时，先推进到判别点，而不是先辩论选型。
3. **用预设死刑条件杀线**——立项时写清「出现什么数据就停」，而不是失败后开会。
4. **把「能不能用」和「该不该发」分成两个门**——试验门全绿只是发布评审的入场券。

> 本 skill 设计为**显式调用**（`disable-model-invocation: true`）：frontmatter 的 description
> 只用于在用户点名「曼哈顿模式」时匹配到它，不参与自动触发。

## 准入判定（开工前 3 问）

1. 是否存在 **≥2 个互相竞争的方案**，且单一方案没有明显优势？
2. 关键参数（工期 / 成本 / 性能）的不确定度是否**跨数量级**，而不是 ±50% 内？
3. 失败的代价是否**远大于**并行探索成本，且有真实截止时间？

判定结果：

- **任一答「否」** → 不启用本模式，直接常规规划，并说明理由。
- **1、3 是，2 否（±50% 内）** → 走**轻量通道**：只做目标 + 授权 + 单线卡（含单一死刑条件）+
  试验门 / 发布门简版；跳过并行与裁决，并明确声明「本次为轻量通道」。
- **3 个全「是」** → 标准 / 全量模式，继续往下。

**退出条件**：运行中若 Q2 转为「能估到 ±50%」、或判别点收敛到单一方案，**立即退出**
本模式，改为常规执行，并在 `decisions.md` 记一条退出记录（原因 + 后续做法）。

## 开工三件事（第一轮回复内完成）

1. **声明身份与隔离方式**：AI 同时承担 Groves 与执行层，两者分开发言（见「发言纪律」）。
   明确说明：有子 agent 时每线独立上下文；无子 agent 时是**单上下文模拟，隔离靠纪律不靠机制**。
2. **建产品目录**：项目根目录建 `.manhattan/`，开段先读上一段产物，
   **未落盘即视为未完成**。文件清单见 [templates.md](templates.md)。
3. **选模式并说明理由**：

| 模式 | 适用 | 并行宽度 | 阵容 |
|---|---|---|---|
| 轻量通道 | 不确定度 ±50% 内，需缓冲 | 1 线 + 缓冲 | 单 AI，一身份 |
| 标准 | 2–4 条候选路线，判别点 1–2 个迭代内到达 | 2–4 条 | 单 AI + 角色切换 |
| 全量 | 路线 ≥5，或需要隔离环境 / 独立预算 | 按子 agent 数 | 每线一个子 agent / 独立分支 |

**并行宽度怎么算**（不要拍脑袋）：

1. 先列 **3–6 个候选方案**（含「不做 / 买现成」这类兜底）。
2. 两两问：**有没有一个判别实验能分出胜负？** 不能 → 合并成一个方案。
3. 判据「共享核心假设」或「>50% 实现重叠」的，合并（那是伪并行）。
4. 剩下的取 **2–4 条**，且不超过当前可并发的子 agent / 人力数；资源只够 1 条就回到轻量通道。

## 发言纪律与签字协议

- 每条消息以身份开头：`【Groves】`、`【技术线 A】`、`【行政】`。裁决会议只由 Groves 发言。
- Groves 只消费**判别点报告**（数据、结论、代价），不掺执行细节；技术身份只交报告，不做路线裁决。
- 用户是 Oppenheimer：**路线取舍、杀线、发布必须用户明确签字**。
  **签字协议**：单独一轮只问一句「是否批准 <具体动作>？」；用户回复「批准 <动作>」才算；
  未回复即阻塞，**不得默认通过、不得用「按你之前的授权」代签**。
- 行政身份接走一切非技术琐事（环境、依赖、文档、进度记录），但不得替用户做技术决策。

## 八段工作流

每段的产物、完成判据、进入下一段前提，模板见 [templates.md](templates.md)。

### 1 作战目标
- 产物：`objective.md`
- 完成判据：交付物可被第三方一句话验收；截止外部给定；验收测量与制造**物理独立**
  （软件域映射：独立测试集 / 外部评审 / 用户实测，而不是同一套开发脚本）；有不做清单；用户点头。
- 进入前提：用户确认这一版目标。

### 2 授权
- 产物：`charter.md` + 用户口述的瓶颈重述
- 完成判据：用户独裁 / AI 先斩后奏（含预算上限）/ 必须会签三类事项逐条写明；用户已用自己的话重述瓶颈。
- 进入前提：瓶颈重述与作战目标一致；不一致回第 1 段。

### 3 /grill
- 产物：并行方案清单 + 每条线的开线理由（写入 `lines/` 前的草稿）
- 完成判据：准入 3 问 + 本段 3 问（Q1/Q2/Q7）问完；并行宽度按上面的算法算出并记录；
  四条并行判据全满足才开线：优劣不确定、判别信息只能做出来才有、等待代价高于并行代价、输掉的线仍有可回收产出。
- 进入前提：用户确认并行宽度。

### 4 招募
- 产物：`tree.md`（问题分解树）、`briefing.md`（底课）、`lines/*.md`（线卡）、降级顺位
- 完成判据：每节点单一负责人且短板有协调人；每线有判别点 / 时间 / 预算 / 死刑条件 / 可回收产出；
  底课全员同版本；第一个里程碑前完成一次范围重估。
- 进入前提：线卡全部有死刑条件与签字人；降级顺位唯一。

### 5 并行推进
- 产物：`reports/<线名>-<日期>.md`（判别点报告）
- 完成判据：基建（评估基准 / 夹具 / 数据管线）先于方案代码；线内透明、线间只走接口协议；
  高风险线放隔离分支或独立目录。
- 进入前提：至少一条线到达判别点，报告可复现。

### 6 技术裁决
- 产物：`decisions.md` 追加一条 + 更新 `assumptions.md`
- 完成判据：裁决会议**只收判别点报告**；触发数据可复现；属于四种裁决之一；用户签字；淘汰记录写明
  「在什么目标、什么假设下淘汰」。
- 进入前提：每条在跑的线都有下一个判别点或已裁决。

### 7 试验门
- 产物：`gate-test.md`（检查单）+ 试验报告
- 完成判据：验收测量与制造物理独立（有证据）；矛盾读数默认「产品有问题」并闭环；
  「规格外但没出事」二选一（改规格或消除偏差，没有第三状态）；同一问题被标「已知」≥3 次升级为阻塞。
- 进入前提：检查单全部勾选，结论为通过。

### 8 发布门
- 产物：`gate-release.md`（检查单）
- 完成判据：试验门全绿只是入场券；评审席位含承担后果方；议程包含影响面 / 回滚（含演练）/ 时机；
  技术负责人无单独否决权；技术评审与发布评审不是同一批人。
- 进入前提：发布结论签字。

## 四种裁决（第 6 段）

| 裁决 | 触发 | 动作 |
|---|---|---|
| 杀线 | 死刑条件触发且判别实验可复现 | 评估救线方案给出时限代价 → 用户签字 → 遣散该线、回收产出、资源转向幸存线 |
| 补线 | 目标从「单线打满」降为「多线拼配额」 | 翻检淘汰档案：早期「在旧目标下不划算」的方案在新目标下重审 |
| 串联 | 各线优势区间互补且中间产物可用单一标量度量 | 竞争改流水线：A 粗筛喂 B 精排，输家变上游 |
| 探索线降配 | 判别信息表明「本期用不上」 | 收缩不清零：归档产出、留最小监控，理由改写为「下一局」 |

杀线只适用于争夺同一交付物的并行线；对跨时间尺度的探索线误用杀线 = 烧掉下一局的种子。

## 红线（不可迁移的战时特例）

- 不搬：针对人的保密审查、无限预算假设、军事隐喻管理团队、封闭居住式管控。
- 「全都要」永远和「降级清单」成对出现，只学前一半是最常见的误用。
- **术语约束**：作战、杀线、处决、试验门等军事词只用于本 skill 的内部文书；
  对用户、队友与外部沟通时改写为「目标 / 中止 / 复评 / 验收」，避免把隐喻带进真实管理。

## 自检清单（任何阶段可查）

- [ ] 准入判定做了吗？当前模式（轻量 / 标准 / 全量）说清楚了吗？
- [ ] 发言身份标了吗？Groves 有没有在掺执行细节？
- [ ] 这一步的产物落到 `.manhattan/` 了吗，还是只在聊天里？
- [ ] 每条在跑的线都有死刑条件和签字人吗？
- [ ] 今天的决策消费的是判别点报告，还是观点 / 工期压力？
- [ ] 需要签字的动作，用户是否明确回复了「批准 <动作>」？
- [ ] 有没有把战时特例当默认前提？有没有该退出本模式却还在走流程？

## 复盘与沉淀（交付后 10 分钟）

写 `retro.md`，回答三问：哪条线本可以更早被杀 / 更早补？哪个验收测量其实不独立？
哪些假设变了但没触发重审？可复用的结论补进 `corpus/cards/`（一卡一算子），**不要直接写进 SKILL.md**。

## 中断与恢复

新会话继续同一项目时：先读 `.manhattan/` 下的 objective / charter / tree / lines / reports /
decisions / assumptions，【Groves】用 5 行总结现状（目标、在跑几条线、各自下一个判别点、待签字事项），
再问「下一步」。
