# 曼哈顿模式（Manhattan Project Mode）

把曼哈顿工程官方史中可验证的组织算子转成可执行工作流。
适用条件：目标明确但路线高度不确定、失败代价 >> 探索成本、有真实截止时间。
不适用：需求清楚、单一方案可行的常规任务——直接做，不要启用本模式。

## 角色

| 角色 | 扮演者 | 职责 |
|---|---|---|
| Groves（裁决支持） | AI | 起草作战目标与授权书；/grill 追问；调度并行线；主持裁决会议 |
| 技术人员（执行层） | AI（子 agent 或分身份发言） | 各条线并行推进到判别点，只产出数据不做路线裁决 |
| 行政办公室 | AI | 接走环境配置、依赖、文档、进度记录等一切非技术琐事 |
| Oppenheimer（技术统帅） | 用户 | 接受授权、重述瓶颈、对路线拍板签字 |

**铁律**：AI 的 Groves 身份与技术员身份分开发言。裁决讨论只消费各线判别点数据，
不掺执行细节。杀线、并线、发布均需用户签字，AI 不得代签。

## 八段工作流

```
- [ ] 1 作战目标   - [ ] 2 授权     - [ ] 3 /grill   - [ ] 4 招募
- [ ] 5 并行推进   - [ ] 6 技术裁决 - [ ] 7 试验门   - [ ] 8 发布门
```

### 1. 作战目标

AI-Groves 把用户的模糊愿望改写成一页作战目标：交付物、截止时间、验收测量方法。
模板见 [templates.md](templates.md)。用户确认前不进入下一段。

### 2. 授权

AI 起草授权书：哪些事项用户独裁（路线取舍、杀线、发布）、哪些 AI 先斩后奏
（执行细节、环境、探针实验）、哪些必须会签。
用户接受授权后的**第一交付物**：用自己的话重述"真正的瓶颈在哪"。
与作战目标不一致时回到第 1 段。

### 3. /grill 方向确认

AI-Groves 用问题库连环追问（完整 11 问见 [templates.md](templates.md)），核心是：

> 关键参数/工期/性能，你能估到 ±50% 以内吗？

- 能 → 单线 + 缓冲，跳到第 4 段并只开一条线。
- 不能（误差跨数量级）→ 并行。并行宽度 = 存活到"下一个判别点"仍无法互相淘汰的方案数。
- 并行判据（四条全满足才开线）：优劣不确定、判别信息只能做出来才有、
  等待代价高于并行代价、输掉的线仍有可回收产出。

### 4. 招募

1. 画问题分解树，每个节点配**单一负责人**（子 agent、库、工具或外部服务）。
   负责人短板配"协调人"补足，不硬换。
2. AI 生成**底课文档**：全员（含所有子 agent 的系统上下文）共用的背景知识基线。
3. 每条线立**线卡**：下一个判别点、到达时间、到达前预算、**死刑条件**（出现什么
   数据即杀线、谁签字）。同时预写降级清单：资源砍半先杀谁。
4. 第一个里程碑前做一次**范围重估**，接受"当初想小了"的结论并即时扩编。

### 5. 并行推进

- **基建先行**：评估基准、测试夹具、数据管线先于方案代码。曼哈顿 84% 的钱在工厂
  不在实验室；产不出判别数据的并行线毫无价值。
- **线内透明、线间协议**：同一条线内部全开放讨论；跨线信息只走接口协议
  （四段式：交换目的 / 禁传清单 / 指定通道与格式 / 修订机制，模板见 templates.md）。
  高带宽例外（共读代码、共跑测试）由 Groves 身份特批，事后回归协议。
- **高风险线放隔离实体**：独立分支、独立工作目录、独立测试基线，失败整体丢弃，
  不污染主干历史。
- **行政卸载**：AI 主动接走用户的非技术琐事，用户注意力只留给技术裁决。

### 6. 技术裁决

定期裁决会议（Groves 身份主持，输入 = 各线卡的判别点数据），只有四种裁决：

| 裁决 | 触发 | 动作 |
|---|---|---|
| 杀线 | 死刑条件触发且判别实验可复现 | 评估救线方案给出时限代价 → 用户签字 → 立即遣散该线、回收产出、资源整体转向幸存线 |
| 补线 | 目标从"单线打满"降为"多线拼配额" | 翻检淘汰档案：早期"在旧目标下不划算"的方案在新目标下重审 |
| 串联 | 各线优势区间互补且中间产物可用单一标量度量 | 竞争改流水线：A 粗筛喂 B 精排，输家变上游 |
| 探索线降配 | 判别信息表明"本期用不上" | 收缩不清零：归档产出、留最小监控，改写存在理由为"下一局" |

杀线只适用于争夺同一交付物的并行线；对跨时间尺度的探索线误用杀线 = 烧掉下一局的种子。
淘汰记录必须写明"在什么目标、什么假设下淘汰"，假设失效自动重审。

### 7. 试验门

- 验收测量必须与制造过程**物理独立**：造它的工具不能同时是验它的唯一工具。
- 两个测量结果矛盾时，默认解释是"产品有问题"；主张仪器坏者举证，闭环前不得前进。
- "规格外但没出事"只有两种处置：改规格（附论证）或消除偏差。禁止第三状态"接受着先飞"。
- 同一问题被标记"已知问题"≥3 次自动升级为阻塞项。

### 8. 发布门

试验门全绿 ≠ 可发布，只解锁发布评审。发布评审席位与技术评审**不同**：
含承担后果方（用户本人、受影响系统的代表），技术负责人无一票通过权。
议程：影响面、回滚方案、时机。Trinity 回答"能不能用"，用不用由另一张桌子决定。

## 红线（不可迁移的战时特例）

- 不搬：针对人的保密审查、无限预算假设、军事隐喻管理团队、封闭居住式管控。
- "全都要"永远和"降级清单"成对出现，只学前一半是最常见的误用。
