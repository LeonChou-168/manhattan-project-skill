# 文书模板

四种文书 + grill 问题库。所有文书一页以内，超过说明想复杂了。

## 作战目标（第 1 段产出）

```markdown
# 作战目标：<项目名>
- 交付物：<可验收的东西，一句话>
- 截止：<日期或触发事件>
- 验收测量：<用什么方法测、谁测、测量工具是否独立于制造过程>
- 不做清单：<明确排除的范围>
```

## 授权书（第 2 段产出）

```markdown
# 授权书
- 用户独裁事项：路线取舍、杀线签字、发布签字、<按项目补充>
- AI 先斩后奏事项：执行细节、环境配置、探针实验（预算上限 <X>）、<补充>
- 必须会签事项：改作战目标、改死刑条件、扩编制
- 用户第一交付物：重述真正的瓶颈（一段话，与作战目标对照）
```

## 线卡（第 4 段产出，每条并行线一张）

```markdown
# 线卡：<方案名>
- 负责人：<单一负责人；短板由协调人 <谁> 补足>
- 下一个判别点：<什么实验/基准，产出什么数据>
- 到达时间：<日期>；到达前预算：<时间/成本上限>
- 死刑条件：出现 <什么可复现数据> 即杀线，签字人：用户
- 可回收产出：<即使被杀，哪些部件/知识可移交>
- 降级顺位：<资源砍半时本线排第几个被杀>
```

## 接口协议（第 5 段，跨线信息交换）

```markdown
# 接口协议：<线A> ↔ <线B>
1. 交换目的：仅限对双方工作都有利的信息
2. 禁传清单：<各自的中间结论、未验证猜想、进度评价>
3. 指定通道：通过 <artifact 路径/schema> 传递；联系人：<谁>
4. 修订机制：任一方申请、Groves 身份批准后修订
5. 高带宽例外：需 Groves 特批，事后回归本协议
```

## 裁决记录（第 6 段，每次裁决会议一条）

```markdown
- 日期 / 裁决类型（杀线|补线|串联|探索降配）/ 触发数据 / 签字人 / 资源去向
- 若为淘汰：在什么目标、什么假设下淘汰（假设失效自动重审）
```

## /grill 问题库（第 3 段使用，按序追问）

1. 交付物是什么？谁验收？验收测量与制造过程是否独立？
2. 关键参数你能估到 ±50% 以内吗？不能——我们开几条线？
3. 每条线的下一个判别点是什么、何时到、到达前花多少？
4. 这条线出现什么数据就地处决？谁签字？
5. 资源砍半先杀谁？
6. 两条线的中间产物能不能互相喂？交接格式是什么？
7. 需求里哪些指标是物理/用户约束、哪些是立项话术？
8. 试验全绿之后，谁坐在发布评审桌上？
9. 用你自己的话说：这个项目真正的瓶颈在哪？（授权后第一问）
10. 哪些琐事在消耗你的注意力？列出来，我接走。
11. 有没有一条"本期用不上但下一局重要"的探索线？给它封多少预算？
