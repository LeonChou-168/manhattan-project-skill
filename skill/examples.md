# 示例：给知识库加中文检索（标准模式 · 2 条线）

> 虚构场景，用来说明八段流程在真实对话里长什么样，数字都是编的。

## 场景

内部知识库 10 万篇中文文档，3 周内上线全文检索，p95 < 300ms。只有用户一个开发 + AI。
候选路线：

- **A**：SQLite FTS5 + jieba 分词——集成快、生态成熟，但召回率存疑。
- **B**：DuckDB + BM25 扩展——排序质量可能更好，集成成本未知。

不确定性：中文分词在真实语料上的召回率无法纸面判断，可能差一个数量级；延期代价远大于并行 1.5 天的成本。

## 第 1–2 段（产物节选）

```markdown
# 作战目标：知识库中文检索
- 交付物：知识库站内检索，支持 200 条固定评测查询
- 截止：3 周后（运营侧活动上线）
- 验收测量：留出集 recall@10 与 p95 延迟，独立脚本测量，不复用开发脚本
- 当前最大不确定性：分词召回率
- 不做清单：不做语义向量检索、不做多语言
- 用户确认：2026-08-20「就按这个来」
```

```markdown
# 授权书
- 用户独裁：选 A/B、杀线、上线
- AI 先斩后奏：语料清洗、分词词典、基准脚本（单次 ≤ 4 小时）
- 必须会签：改验收指标、扩线、推迟截止
- 用户第一交付物：「真正的瓶颈是召回率能不能过 0.8，不是接口长什么样。」
```

## 第 3 段 /grill（节选，只问 Q1/Q2/Q7）

【Groves】Q1：交付物是什么、谁验收？验收测量和制造过程独立吗？
【用户】站内检索，我验收；用留出集测 recall 和 p95，独立脚本跑。
【Groves】Q2：关键参数能估到 ±50% 内吗？
【用户】不能，中文分词在业务语料上完全没数。
【Groves】Q7：需求里哪些是硬约束、哪些是立项话术？
【用户】3 周截止和 p95 是硬的；「支持语义搜索」是随口加的，进不做清单。
【Groves】结论：不确定度跨数量级，走标准模式；并行宽度按算法：候选 A/B/买云服务，
A 与 B 有可区分的判别实验，云服务因合规先排除 → 开 2 条。
判别点统一为「同一 200 条真实查询的 recall@10 + p95」；每条线预算 1.5 天、1.5 天。

## 第 4 段（线卡与底课节选）

```markdown
# 线卡：A · SQLite FTS5 + jieba
- 负责人：AI-技术线 A
- 下一个判别点：200 条查询上的 recall@10 与 p95
- 到达时间：第 2 天中午；到达前预算：1.5 天
- 死刑条件：到达时 recall@10 < 0.75，或 p95 > 400ms，用户签字
- 可回收产出：中文清洗脚本、自定义词典
- 降级顺位：第 2 个被杀
```

```markdown
# 线卡：B · DuckDB + BM25
- 负责人：AI-技术线 B
- 下一个判别点：同一 200 条查询的 recall@10 与 p95
- 到达时间：第 2 天傍晚；到达前预算：1.5 天
- 死刑条件：recall@10 < 0.75，或集成需要改现有 API 契约，用户签字
- 可回收产出：排序调参记录
- 降级顺位：第 1 个被杀
```

底课：同一份语料目录、同一份 200 条查询、同一套 API 契约，两条线共用。

假设登记（节选）：A1「jieba 默认词典对业务术语够用」——依据：通用语料测试；失效条件：300 条业务查询上 recall 掉 10 个百分点以上。

## 第 5–6 段：裁决

第 2 天，两条线交回同一张评测表：

| 线 | recall@10 | p95 | 备注 |
|---|---|---|---|
| A | 0.71 | 480ms | 词典缺业务术语 |
| B | 0.83 | 210ms | 集成需新增一次查询转换层 |

【Groves】A 的死刑条件触发（recall 与延迟双超），建议杀 A；B 存活。
【用户】签。
【Groves】写入 decisions.md：A 线遣散，CJK 清洗脚本与自定义词典移交 B；B 获得原 A 的 0.5 天预算。

## 第 7–8 段：两门

第 7 段试验门：另写一份独立测量脚本，在 200 条留出查询上测，报 recall@10 = 0.83、p95 = 210ms。
开发脚本报的是 0.88——两表矛盾，按「产品有问题」处理，复查发现开发脚本漏统计了空结果查询，指标以独立脚本为准。

第 8 段发布门：试验全绿只解锁评审。发布评审桌上是用户 + 运维同学（承担后果方），
议程：影响面（知识库全量 10 万篇）、回滚方案（保留旧接口开关）、时机（活动前一周灰度）。技术负责人无单独否决权。

## 复盘（retro.md 节选）

1. 哪条线本可以更早被杀？A 没有——判别点按计划到达，提前杀反而拿不到可比数据。
2. 哪个测量其实不独立？开发脚本与实现同源，正是「独立测量」抓到了统计 bug。
3. 哪些假设失效没重审？A1 在 300 条查询上失效，已重审并改用自定义词典。
4. 沉淀什么？该现象已被 HST-TEST-01 覆盖，不新增卡片。

## 从这个例子能带走

- 模式判断看不确定度：±50% 用轻量（单线 + 缓冲），数量级才升级到标准模式。
- 判别点是「可比较的标量 / 表格」，不是「开发完成」。
- 死刑条件在立项时写死，触发时 10 分钟就能完成一次裁决。
